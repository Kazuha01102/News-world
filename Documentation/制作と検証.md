## ニュース：確定した仕様と未検証点

公式仕様ではAVProがYouTube Liveなどに対応。Unity Video Playerではこれらのライブ非対応。AVProとYouTube URLの再生確認にはVRChatクライアントが必要。Unity Play ModeやClientSimで映像再生成功とは判定できない。

重要：`new VRCUrl(string)` はEditor時のみ。String Loadingで得た任意の文字列をそのまま動画URLに変える方式は採用できない。URL入力欄から利用者が入力したVRCUrl、または事前登録VRCUrlを使う。

候補A：`https://www.youtube.com/watch?v=Anr15FA9OCI`
TBS公式 `https://newsdig.tbs.co.jp/list/live` の24h DIG LIVE埋め込みから2026-10-27に確認。実際のライブ継続・地域制限・VRChat再生は未確認。

候補B：`https://www.youtube.com/@tbsnewsdig/live`
同局の固定入口をURL解決できるか調べる比較用候補。別局の予備チャンネルではない。複数ライブがある場合の選択は保証されない。解決できなければ手動watch URLへ戻す。

ニュースや配信元映像を自前サーバーで保存・中継しない。各クライアントが配信元から再生する。公式配信であることは、ワールド利用許諾の確認を代替しない。公開前に配信元・YouTubeの利用条件を確認する。

## 作成した最小試作

- `NewsPlaybackProbe.cs`：所有者が初期化、VRCUrl・再生／停止・変更番号を手動同期。OnPlayerJoinedから再生変更をしない。
- 各クライアントでAVPro再生。ローカルの再接続、音量±、ミュート。再接続は他の視聴者へ影響させない。
- 新規URL読み込みの間隔6秒以上、エラー自動再試行は最大3回（6/12/18秒）。予備候補や手動入力は利用者が選ぶ。
- 同じURLが再通知されても再生できている既存視聴者には再ロードしない。
- 停止は共有。ライブを対象とし、録画動画のシーク同期は対象外。全員のライブ位置の完全一致は保証しない。
- `NewsMetadataProbe.cs`：固定VRCUrlのテキスト取得診断。成功・HTTPエラーを表示。最大3回再試行。取得内容を更新しても動画に介入しない。公開先がないためendpointは空。
- `NewsProbeBuilder.cs`：メニュー `Night Home > Create News Test Scene` でSDKのAVProサンプルを利用した独立検証シーンを生成する。既存の同名シーンは上書きしない。

## 自動取得の選択肢

1. 最優先：固定の公式 `/live` URLがVRChatのURLリゾルバーで動くかを実機比較。成立すれば外部サービス不要。ただし再生中の配信終了後まで自動追従するとは限らない。
2. 事前登録した複数VRCUrlから外部JSONのchannelKeyで選択。文字列から任意URLは作らず、固定候補から選ぶ。watch IDが変わる場合はワールド更新が必要。
3. 外部で最新watch URLを取得し、ワールド内に文字列として表示。利用者がURL入力欄へ入力して再生。自動取得と手動適用の折衷。
4. 自前の固定HTTPS入口から最新の公式watch URLへリダイレクト：動画側のリゾルバー・最終ホスト・信頼設定によるため未検証。実機成功までは採用しない。String Loadingのリダイレクト動作とは分けて試験する。

外部運用が必要な場合の案：サーバーの定期ジョブ→YouTube Data API `search.list`（公式channelId、eventType=live、type=video）→動画状態・チャンネルを検証→UTF-8 JSONをHTTPSの固定パスへ公開。APIキーはサーバー環境変数またはCI Secretsだけに保存する。Unity、Udon、公開JSON、Git履歴へ入れない。映像・期限付きgooglevideo URLは取得・中継しない。

Google公式の2026-10-15更新資料ではsearch.listは既定100呼び出し/日。2局を1時間おきなら48回/日（ページ追加や再試行も消費）。最新のGoogle Cloud Consoleの割当を運用時に再確認。常時数分ごとの検索はこの枠を超える。失敗時に正常な既存情報を削除しない。generatedAtUtc、channelId、videoId、isLive、schemaVersionを公開し、古いデータや未知の局を拒否する。

費用：固定URL方式は追加サービス不要。外部ジョブとJSON配信は既存の無料枠で試せる可能性があるが、ホスティングの規約・商用可否・定期実行・通信・API割当次第。現時点で契約・課金・公開先作成・キー発行はしていない。金額を0円保証しない。

String Loadingは5秒制限。GitHub Pagesの `*.github.io` などが公式許可リストにある。任意ホストは各自のAllow Untrusted URLs設定が必要。リダイレクトに依存せず最終HTTPS URLを固定登録する。Public/Group Publicの未信頼動画ホストには、利用者設定に加えVRChatサイトのワールド設定 `Video Player Allowed Domains` が必要。独自リダイレクト入口は途中ホストを含め実機検証する。

## 初心者向け：最初の再生テスト

1. Unity Hubの「Projects」→「Add」→「Add project from disk」でこの `NightHomeWorld` フォルダーを選ぶ。2022.3.22f1で開く。アバターのプロジェクトと名前・フォルダーを見比べる。
2. 初回のパッケージ取り込みが終わるまで待つ。上部メニュー `Window > General > Console` で赤エラーがないか確認する。
3. Projectウィンドウの `Assets > NightHome > NewsPlaybackTest` をダブルクリック。まだシーンがなければ上部 `Night Home > Create News Test Scene` を一度実行する。
4. 上部 `VRChat SDK > Show Control Panel` を開き、Authenticationで自分のVRChatアカウントにログイン。パスワードをこのチャットへ送らない。
5. BuilderタブでWindows向けであることを確認。SDKが表示する必須修正があれば内容を確認して適用。「Build & Test」でPC版VRChatを起動する。公開アップロードは不要。
6. 最初の候補が再生するか確認。画面下のPrimary、Fallback、URL入力→Manual、Stop、Play、Reconnectを試す。Muteと音量は本人だけに作用する想定。
7. 映像が出ないときは画面のエラーとPCログを記録。クライアントログは通常 `%USERPROFILE%/AppData/LocalLow/VRChat/VRChat/output_log_*.txt`。Generic、InvalidURL、AccessDeniedなどとURLを区別する。認証Cookieやパスワードは共有しない。
8. `/live` が失敗しwatch URLが成功した場合は、まず固定watch URL＋手動更新で進める。取得URLを文字列のまま動画へ渡す回避策は使わない。
